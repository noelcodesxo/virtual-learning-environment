The model does not report percentage completion. This indicator is intentionally indeterminate rather than misleading.

Design decision: the app has one navigation rail and one content area. Chat history, recent exams, and document management become contextual content—not permanent second sidebars. The Library is first-class, rather than hidden inside the Exam picker.
  1. Information architecture: replace the current global Chat/Exams switch plus nested page sidebars with the persistent Workspace/Library rail shown above. Retain routes for direct links, but make transitions feel like one application shell.
  2. Library: add a resource catalog view with document type, source filename/title, page or chapter count, upload state, detected chapters, and an add-document action. Add a library API contract rather than repurposing the Exam-only books response.
  3. Chat: keep conversation history inside the Chat view, with a compact “New chat” action in the top bar. Remove the page-specific left rail and simplify copy to “Ask about your library.”
  4. Exams: make recent exams a compact top-bar/panel action; use one centered setup card with resource, chapter, and question count. Update labels from “Book” to “Resource” where PDFs are valid.
  5. Generation status: expose real local phases (source selection complete; request dispatched). While the synchronous LLM call is pending, show “Waiting for model response” with an indeterminate indicator. Do not show a fabricated percentage. Add a later streaming/job-status phase only if the provider supports verifiable progress events.
  6. Quality bar: preserve keyboard navigation, semantic labels, reduced-motion behavior, and responsive layout. Add component/API tests for navigation, library states, and generation-status transitions; manually test desktop and mobile layouts.
